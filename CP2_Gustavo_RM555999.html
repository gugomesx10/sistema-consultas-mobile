3. Exemplo de Refatoração — HomeScreen

Mostrando o antes e depois da refatoração da tela HomeScreen como exemplo do padrão aplicado nas 7 telas.

❌ ANTES — Styles dentro da tela

// src/screens/HomeScreen.tsx — tudo junto import { View, Text, StyleSheet } from "react-native"; export default function HomeScreen() { return ( <View style={styles.container}> <Text style={styles.titulo}>Sistema de Consultas</Text> </View> ); } // styles ficavam aqui embaixo no mesmo arquivo const styles = StyleSheet.create({ container: { flex: 1, backgroundColor: "#f5f5f5" }, titulo: { fontSize: 28, fontWeight: "bold", color: "#79059C" }, // ... mais estilos });

✅ DEPOIS — Separado em 2 arquivos

1. HomeScreen.tsx (apenas componente)

// src/screens/HomeScreen.tsx import React from "react"; import { View, Text } from "react-native"; import styles from "../styles/home.styles"; export default function HomeScreen() { return ( <View style={styles.container}> <Text style={styles.titulo}> Sistema de Consultas </Text> </View> ); }

2. home.styles.ts (apenas estilos)

// src/styles/home.styles.ts import { StyleSheet } from "react-native"; const styles = StyleSheet.create({ container: { flex: 1, backgroundColor: "#f5f5f5", }, titulo: { fontSize: 28, fontWeight: "bold", color: "#79059C", }, // ... demais estilos }); export default styles;
Resultado: O mesmo padrão foi aplicado para todas as 7 telas. A aplicação continuou rodando normalmente sem nenhuma alteração visual.

5. Tipagem TypeScript — Types e Interfaces

O projeto usa tipagem forte com TypeScript. Separei type para estruturas simples e interface para objetos mais complexos com relacionamentos.

Types (src/types/)

📄 Especialidade (type)

Representa a especialidade médica (cardiologia, ortopedia, etc.)

export type Especialidade = { id: number; nome: string; descricao?: string; // opcional };

📄 Paciente (type)

Dados do paciente cadastrado no sistema

export type Paciente = { id: number; nome: string; cpf: string; email: string; telefone?: string; // opcional };

📄 StatusConsulta (union type)

Define os únicos 4 status possíveis para uma consulta — se colocar outro valor, o TypeScript dá erro.

export type StatusConsulta = "agendada" | "confirmada" | "cancelada" | "realizada";

Interfaces (src/interfaces/)

📋 Medico (interface)

Interface do médico — usa o type Especialidade como referência

export interface Medico { id: number; nome: string; crm: string; especialidade: Especialidade; ativo: boolean; }

📋 Consulta (interface)

Interface principal — junta Medico, Paciente, StatusConsulta

export interface Consulta { id: number; medico: Medico; paciente: Paciente; data: Date; valor: number; status: StatusConsulta; observacoes?: string; }
Por que separei type e interface?
• type → para estruturas simples, union types e alias de tipos
• interface → para objetos que têm relacionamentos com outros tipos (Medico referencia Especialidade, Consulta referencia Medico e Paciente)
• Types ficam em src/types/, Interfaces ficam em src/interfaces/

Dificuldades encontradas

  • No começo precisei entender bem a organização de pastas pra não errar o caminho do import (../styles/ em vez de ./styles/).
  • O Alert.alert do React Native não funciona na web (navegador), tive que adaptar pra usar window.alert quando rodava no browser.
  • Precisei prestar atenção pra não esquecer o export default styles nos arquivos de styles, senão o import quebrava.
  • Tive que aprender a trabalhar com branches separadas e fazer merge com --no-ff para manter o histórico organizado.

Aprendizados

  • Separar os estilos em arquivos dedicados deixa o código muito mais organizado e fácil de manter.
  • O Git Flow com branches por tela ajuda a isolar as mudanças e evitar conflitos.
  • Aprendi a usar React Context pra compartilhar dados entre telas sem precisar passar props manualmente.
  • Commits semânticos (feat:, refactor:, fix:) ajudam a entender o histórico do projeto.
  • A separação de responsabilidades (UI vs Styles) é uma boa prática que facilita o trabalho em equipe.
